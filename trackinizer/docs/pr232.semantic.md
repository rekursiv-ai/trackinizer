# PR #232: semantic-search defects and verification plan

## Context

- PR: <https://github.com/rekursiv-ai/trackinizer/pull/232>.
- Requirement: <https://github.com/rekursiv-ai/trackinizer/issues/11>.
- Reviewed commit: `3733249dc64f31dbb2d8ac05c632c31b0f0cf091`.
- Comparison base: `9d293160edae08e407e47625aee543f663a4f741`.
- Scope: HTTP embedding, indexing writes, similarity queries, and web fallback.
- Paths below are repository-relative; line references describe the reviewed commit.
- This report records findings and proposed fixes, not implemented changes.
- Reproductions used isolated databases, mocked endpoints, or synthetic local credentials.
- No real credentials were disclosed during verification.

## Provenance summary

- Seven confirmed defects are introduced by this PR: N1–N7.
- Two confirmed mechanisms predate it: replay ordering and transactional batch embedding.
- HTTP embedding makes those existing mechanisms operationally significant.
- Existing library callers could already inject slow or failing embedders.
- Description replay failures additionally extend the existing problem into a new path.
- Remaining observations distinguish documentation errors, coverage gaps, and unproven design concerns.

## New defects

### N1. Malformed upstream credentials leak through API errors

- **Status:** Open; high severity; reproduced.
- **Evidence:** `trackinizer/server/embedder_http.py:109-128` interpolates raw HTTP exceptions.
- **Exposure:** `trackinizer/server/api/app.py:286-292` returns exception text to API callers.
- **Access:** `trackinizer/server/api/query.py:260-266` permits similarity queries from viewers.
- **Repro:** configure a local endpoint with `api_key="sk-SYNTHETIC-secret\n"`; request embedding.
- **Observed:** the resulting `ConflictError` contains the complete synthetic credential.
- **Error:** `Illegal header value b'Bearer sk-SYNTHETIC-secret\n'`.
- **Expected:** upstream secrets never appear in caller-visible errors.
- **Question:** which upstream diagnostics can safely cross the API boundary?
- **Discussion:** stripping whitespace fixes this trigger, not the general disclosure mechanism.
- **Fix:** validate credentials during configuration and sanitize upstream errors centrally.
- **Fix:** expose safe error categories/statuses, not raw transport exceptions or response bodies.
- **Red test:** `test_embedding_errors_never_disclose_credentials` uses a newline-containing synthetic key.
- **Guard:** responses and captured logs exclude the credential and Authorization header.
- **Guard:** configuration rejects invalid header values before serving requests.

### N2. Concurrent title/description edits persist stale embeddings

- **Status:** Open; high severity; reproduced against PGlite.
- **Evidence:** `trackinizer/server/store/edit.py:101-115` reads descriptions before embedding title changes.
- **Evidence:** `trackinizer/server/store/edit.py:299-318` reads titles before embedding description changes.
- **Evidence:** `trackinizer/server/store/edit.py:129-142` commits without validating that snapshot.
- **Repro:** pause title embedding after reading the old description.
- **Repro:** commit a description change, then resume the title update.
- **Observed:** both text edits persist, but the vector represents the old description.
- **Measured:** cosine distance from the correct final-text embedding was `1.0965677550611936`.
- **Expected:** committed vectors represent the committed title/description pair.
- **Question:** how can remote embedding avoid locks without sacrificing snapshot consistency?
- **Discussion:** last-writer-wins vectors do not guarantee last-writer-wins combined text.
- **Fix:** read a text snapshot, embed outside transactions, then verify under lock.
- **Fix:** release and retry when either text component changed.
- **Fix:** coordinate both setters through the same consistency-preserving mutation path.
- **Red test:** `test_concurrent_text_edits_preserve_embedding_consistency` controls interleaving using events.
- **Guard:** both commit orders leave vectors matching the final stored text.
- **Guard:** no remote embedding occurs while holding the database transaction.

### N3. Description no-ops depend on embedding availability

- **Status:** Open; medium severity; reproduced.
- **Evidence:** `trackinizer/server/store/edit.py:299-318` embeds before checking unchanged values.
- **Evidence:** `trackinizer/server/store/edit.py:413-415` performs the later no-op check.
- **Repro:** submit with no description, disable embedding, then set description to `None`.
- **Observed:** an unchanged description raises the embedder's failure.
- **Expected:** a no-op requires neither remote computation nor a working endpoint.
- **Question:** where should no-op detection occur without introducing mutation races?
- **Fix:** compare during preflight; preserve transactional rechecks for actual changes.
- **Red test:** `test_description_noop_does_not_embed` installs a failing embedder.
- **Guard:** unchanged and normalized-equivalent values produce no embedding calls or audit writes.
- **Provenance:** title embedding already preceded no-op checks; description embedding is newly introduced.

### N4. Upstream failures are reported as application conflicts

- **Status:** Open; medium severity; HTTP behavior reproduced.
- **Evidence:** `trackinizer/server/embedder_http.py:125-133` raises `ConflictError` for upstream failures.
- **Evidence:** `trackinizer/server/api/app.py:286-292` translates these failures into HTTP 409.
- **Evidence:** `trackinizer/client/client.py:1684-1687` retries selected 5xx responses, not 409.
- **Repro:** make the embedding transport raise `ConnectError`; call `/api/inquiries/similar`.
- **Observed:** HTTP 409 with `code="conflict"`.
- **Expected:** dependency unavailability is distinguishable from conflicting application state.
- **Affected:** submissions, title/description edits, and direct similarity queries.
- **Unaffected:** unrelated mutations do not universally depend on embedding.
- **Question:** which upstream failures are transient, misconfiguration, or invalid responses?
- **Fix:** introduce sanitized upstream error categories with appropriate 502/503 mapping.
- **Fix:** handle upstream rate limiting consistently, with bounded retries where appropriate.
- **Discussion:** combine retry changes with P1 to preserve committed-write replay.
- **Red test:** `test_embedding_outage_maps_to_retryable_status` exercises actual API handlers.
- **Red test:** `test_transient_embedding_failure_retries_without_duplicate_write` preserves one idempotency key.
- **Guard:** genuine application conflicts remain HTTP 409.

### N5. HTTP vector validation permits invalid numerical results

- **Status:** Open; medium severity; reproduced.
- **Evidence:** `trackinizer/server/embedder_http.py:180-195` coerces components and computes naive squared norms.
- **Contract:** `trackinizer/types/embedder.py:36-37` promises fixed-width unit vectors.
- **Repro:** return correctly sized vectors beginning with `"nan"` or `"inf"`.
- **Observed:** normalization returns non-finite vectors.
- **Repro:** return `[1e308, 0, ...]`.
- **Observed:** norm overflow produces an all-zero output vector.
- **Repro:** return a vector containing integer `10**400`.
- **Observed:** uncaught `OverflowError` escapes the controlled endpoint-error boundary.
- **Expected:** finite unit vectors or sanitized, controlled validation errors.
- **Question:** should finite extreme magnitudes normalize successfully or be explicitly rejected?
- **Fix:** validate finite components and normalize using numerically stable scaling.
- **Fix:** contain conversion overflow and preserve fixed-width/nonzero validation.
- **Fix:** replace repeated JSON casts with the project's typed JSON boundary.
- **Red test:** `test_embedding_response_enforces_finite_unit_vectors` parameterizes malformed and extreme values.
- **Guard:** valid outputs have expected width, finite components, and approximately unit norm.
- **Guard:** invalid responses never escape as raw conversion or database errors.

### N6. Semantic fallback ignores explicit search predicates

- **Status:** Open; medium severity; reproduced using existing web fixtures.
- **Evidence:** `trackinizer/server/web.py:124-125` documents field-scoped regex predicates.
- **Evidence:** `trackinizer/server/web.py:182-186` falls back after every zero-hit query.
- **Evidence:** `trackinizer/server/web.py:214-224` embeds raw syntax and only filters distance.

- **Repro:** provide a nearby semantic result titled `Momentum`, distance `0.1`.
- **Observed:** the result is returned despite violating the anchored title predicate.
- **Expected:** explicit predicates remain binding.
- **Question:** where does natural-language recall end and structured filtering begin?
- **Fix:** initially restrict automatic fallback to unqualified natural-language queries.
- **Alternative:** preserve structured predicates while embedding only the natural-language portion.
- **Discussion:** simply stripping regex prefixes still discards user constraints.
- **Red test:** `test_semantic_fallback_preserves_explicit_predicates` covers title and description regexes.
- **Guard:** ordinary paraphrase queries still receive semantic fallback.
- **Guard:** literal matches never invoke remote embedding.

### N7. Whitespace-only similarity queries trigger embedding

## Pre-existing defects exposed by HTTP embedding

### P1. Committed-write replay happens after embedding

- **Status:** Open; medium severity; reproduced against PGlite.
- **Provenance:** base `trackinizer/server/store/submit.py:228` already embedded before the replay probe.
- **Provenance:** base title edits likewise embedded before checking committed change identifiers.
- **New extension:** description edits now follow the same failure-prone ordering.
- **Evidence:** `trackinizer/server/store/submit.py:220-228` embeds before transactional replay.
- **Evidence:** `trackinizer/server/store/submit.py:306-317` contains the later replay probe.
- **Repro:** successfully submit using a fixed idempotency key.
- **Control:** retrying while embedding remains healthy returns the original inquiry ID.
- **Repro:** disable embedding and repeat the identical committed request.
- **Observed:** the retry fails instead of returning the original ID.
- **Expected:** committed replay does not require repeating remote side effects.
- **Question:** how can early replay avoid network work while remaining race-safe?
- **Fix:** check committed keys before embedding; retain transactional replay and collision recovery.
- **Fix:** preserve actor/operation validation and existing change-ID consumption semantics.
- **Discussion:** removing transactional checks would introduce duplicate-write races.
- **Red test:** `test_committed_submit_replays_without_embedding` toggles a controllable embedder.
- **Red test:** equivalent title/description tests cover committed edit identifiers.
- **Guard:** original IDs return without embedding calls or additional audit rows.

### P2. Batch embedding holds the shared database transaction

- **Status:** Open; medium severity; reproduced against PGlite.
- **Provenance:** base batch submissions already embedded each item inside their shared transaction.
- **Evidence:** `trackinizer/server/store/submit.py:328-332` performs inline embedding.
- **Evidence:** `trackinizer/server/store/submit.py:675-694` owns the transaction across all items.
- **Repro:** pause the batch embedder using an event.
- **Repro:** concurrently acquire a connection for `SELECT 1`.
- **Observed:** the read remains blocked during embedding; the 100ms probe timed out.
- **Expected:** remote embedding latency does not monopolize the shared database connection.
- **Question:** how should prepared vectors reach per-kind submission handlers?
- **Fix:** prepare batch embeddings before acquiring the transaction, then pass them through.
- **Fix:** retain atomic row/edge commits and transactional idempotency checks.
- **Discussion:** embedding outside transactions does not require committing batch items separately.
- **Red test:** `test_batch_embedding_does_not_block_database_reads` uses deterministic synchronization.
- **Guard:** a concurrent read completes before releasing the paused embedder.
- **Guard:** failed database writes still roll back the entire batch.

## Additional pre-existing behavior and documentation

### P3. Startup backfill couples availability to embedding

- **Status:** Open design concern; startup failure reproduced, prior progress preserved.
- **Provenance:** synchronous embedding during bootstrap and advisory locking predate this PR.
- **New behavior:** remote backfill defaults off; an environment flag explicitly enables it.
- **Evidence:** `trackinizer/server/store/core.py:257-295` implements skip/opt-in behavior.
- **Evidence:** `trackinizer/server/store/core.py:370-433` holds the bootstrap advisory lock.
- **Repro:** enable remote backfill; make the second row's embedding fail.
- **Observed:** bootstrap raises; the first row's embedding remains persisted.
- **Correction:** the backfill is not one all-or-nothing transaction.
- **Question:** should requested indexing failure prevent the server from starting?
- **Proposal:** separate resumable indexing from startup, with explicit progress and failure reporting.
- **Red test:** a failed row preserves progress without preventing ordinary server operation.
- **Guard:** retries only process missing or stale embeddings.

### P4. Cheap validation and configuration checks occur late

- **Status:** Existing ordering weakness; not exclusively introduced by this PR.
- **Evidence:** `trackinizer/server/api/app.py:127-129` starts the engine before constructing embedding.
- **Evidence:** `trackinizer/server/config.py:127` accepts the backend name without eager validation.
- **Evidence:** `trackinizer/server/store/submit.py:228` precedes later submission validation.
- **Provenance:** engine ordering and submission/title preflight ordering already existed.
- **New exposure:** HTTP configuration and network costs make those choices more consequential.
- **Question:** which checks can safely precede expensive resource acquisition?
- **Proposal:** validate configuration before engine startup; perform cheap write preflight before embedding.
- **Red test:** invalid embedding configuration never starts an engine.
- **Red test:** missing targets and invalid submissions make no embedding calls.
- **Guard:** transactional rechecks still protect against concurrent changes.

### P5. Client retry commentary understates possible duration

- **Status:** Open documentation defect; pre-existing.
- **Evidence:** `trackinizer/client/client.py:1615-1617` describes approximately one-second worst-case waiting.
- **Evidence:** `trackinizer/client/client.py:1666-1687` retries read timeouts and selected 5xx responses.
- **Observed:** each attempt can consume the configured read timeout before retrying.
- **Expected:** documentation distinguishes retry delays from total request duration.
- **Fix:** describe per-attempt deadlines and cumulative retry budgets accurately.
- **Verification:** compare documented timing against configured timeouts and retry counts.
- **Red test:** unnecessary for wording alone; budget behavior requires a separate timing contract.

## Unproven concerns and policy choices

- **Limit validation:** the new similarity route clamps; sibling routes reject invalid limits.
  - Proposal: choose and document consistent behavior; test zero, negative, and excessive limits.
- **Connection pooling:** the new HTTP embedder creates one client per request.
  - Proposal: measure connection overhead before adding shared-client lifecycle complexity.
  - Test: verify connection reuse and explicit shutdown if pooling is adopted.
- **Timeout interaction:** existing client and new upstream timeouts both default to thirty seconds.
  - Proposal: define an overall budget; test delayed upstream responses against that budget.
- **Distance cutoff:** the new `0.8` threshold lacks multi-model calibration evidence.
  - Proposal: measure relevant/unrelated queries before introducing model-specific thresholds.
- **Provider compatibility:** unconditional `dimensions` could fail against unsupported endpoints.
  - Proposal: reproduce against a supported provider before adding request variants.
- **URL validation:** malformed nonblank endpoints fail at first use.
  - Proposal: reject unsupported URL shapes during configuration; test construction-time failures.
- **Constructor exceptions:** configuration faults currently use application-conflict exceptions.
  - Proposal: define explicit configuration/upstream categories; test their documented mappings.
- **Label whitespace:** copied model labels may include unexpected whitespace.
  - Proposal: define normalization explicitly; arbitrary exact labels otherwise remain queryable.
- **Dimension ownership:** duplicated width defaults predate the PR; HTTP inherits StubEmbedder's width.
  - Proposal: centralize schema width only if it reduces actual maintenance complexity.
- **Search scaling:** existing storage lacks an approximate vector index.
  - Proposal: benchmark the new exact search before selecting indexing and recall tradeoffs.
- **Style:** cast formatting and docstring-section preferences lack verified repository mandates.
  - Proposal: follow established conventions without classifying preferences as functional defects.

## Rejected or corrected findings

- **Different limit ceilings:** false; both routes cap results at 1,000.
- **Evidence:** `trackinizer/wire/routes.py:225` defines `MAX_LIST_LIMIT = 1000`.
- **All-or-nothing backfill:** disproven; the first successful embedding survived second-row failure.
- **ANN filter underfilling:** no approximate index exists in the inspected schema.
- **First-embedder selection:** explicitly documented; selecting a stub first is not undisclosed behavior.
- **Strict semantic flag:** requiring `True` matches the documented boolean contract.
- **Numeric coercion:** accepting finite coercible values alone doesn't violate unit-vector output requirements.
- **Tiny-vector normalization:** normalization itself isn't defective; numerical instability is covered by N5.
- **Order-sensitive test embedder:** first-substring matching is explicitly documented.
- **Missing CLI command:** the requested API/library feature doesn't require another CLI verb.
- **Missing description-edit wording:** mentioning title edits doesn't independently prove a false behavioral claim.
